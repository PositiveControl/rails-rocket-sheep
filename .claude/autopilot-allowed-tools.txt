# Tools an autopilot step may use without asking. bin/autopilot passes these to
# `claude -p --permission-mode dontAsk --allowedTools`, and anything not listed
# is denied rather than prompted (docs/system/autopilot.md).
#
# One rule per line, in Claude Code's permission rule syntax. `#` starts a
# comment. Deliberately absent: `gh pr merge` (the driver merges, after checking
# the base), `gh pr ready` and `gh issue close` (the developer's), force pushes,
# and anything that reads credentials.
#
# Not a wall on its own. Rules match by prefix, and several entries the steps
# genuinely need run arbitrary code:
# - `ruby`, `bundle exec` and `bin/rails` (`bin/rails runner`)
# - `find` (`-exec`, `-delete`)
# - `git checkout` (`git checkout -- .` discards work)
# - `gh api`, which can reach the merge endpoint
# So `gh pr merge` or a force push is one `ruby -e` away. This list keeps an
# honest step from wandering. The guard, bin/hooks/autopilot_guard, denies by
# what a command does anywhere in its string, not by its prefix. It and the
# policy are the other two layers (docs/system/autopilot.md, Guard).
