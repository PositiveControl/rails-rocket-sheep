# The API Contract Is Generated From Its Tests

**Applies to:** API mode. A server-rendered app's contract is its HTML, and has no
equivalent artifact.

**Status:** Accepted

**Context:**
A separate JS client needs a written contract. There are three places it can come
from: hand-written, generated from the routes and controllers, or generated from a
running server.

Hand-written drifts the first week nobody is watching. Generated from routes
documents that an endpoint exists and nothing about how it behaves. Generated from
traffic describes only what someone happened to exercise, and gets quieter the less
the API is used.

**Decision:**
`openapi.yaml` is committed and it is a build output, generated by running the
request tests. `bin/rails api:contract` regenerates it; `bin/rails api:contract:check`
exits non-zero when the committed and generated copies differ, and CI runs that.
Every problem `type` raised in a test appears in the document, because the error
shapes are as much the contract as the success shapes. One document per API version.

Generating from tests is what makes an untested endpoint an *undocumented* endpoint —
the state becomes visible rather than comfortable. It is also the reason the
serializer field lists, the filter and sort allowlists, and `optional`/`includable`
are declarations rather than control flow: the generator reads them. Conventions are
in [`../rules/openapi-contract.md`](../rules/openapi-contract.md).

**Consequences:**
- (+) The contract cannot silently rot. A PR that adds an endpoint and leaves the
  document stale fails CI, the same mechanism as a stale `tokens:` figure failing
  `bin/lint-docs`
- (+) A client can be generated from it, and the client repo consumes this one file
  and nothing else
- (+) The pressure to document an endpoint becomes pressure to test it, which is the
  right direction for that pressure to run
- (-) The generator is this app's code to maintain, and it only knows what the other
  rules declare. A field built by hand in an action documents as nothing
- (-) The gate is annoying in exactly the way it is meant to be: regenerating is part
  of the change, not a follow-up
- (-) An endpoint whose tests cover one branch documents one branch. Coverage of the
  suite is now coverage of the contract, with no separate signal for that
